# TD2 Mobile HUD 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the overcrowded mobile combat HUD with compact status and contextual tower controls.

**Architecture:** Keep the current Canvas game and desktop controls. Add a small standalone touch-context UI module and a final, scoped mobile stylesheet; route canvas taps to build/tower contexts, and preserve existing combat functions with optional explicit tower targets.

**Tech Stack:** HTML, CSS, vanilla JavaScript, Node `assert` tests.

**Spec:** `docs/superpowers/specs/2026-11-09-mobile-hud2-design.md`

## Global Constraints

- Do not change save format, balance, assets, or Ansturm.
- Never commit directly to `main`; base on verified `main` SHA.
- Preserve desktop mouse/keyboard workflow.
- No main merge if relevant tests fail; physical Android test remains pending.

## Review Focus

- A touch drag across a build pad must not open a menu.
- Tapping an existing tower targets that tower, not the one near the hero.
- Closing or pausing must not leave an operable hidden context panel.
- Funds or tower-cap changes after opening must not permit an invalid build.
- Other overlays (inventory, story, menus) must not accept world taps.

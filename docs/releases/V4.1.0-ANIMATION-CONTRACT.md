# V4.1.0 directional action production contract

Reference lock: preserve each approved Marcel/Kim/enemy identity, face, glasses, costume, armor, weapon side, camera, overhead lighting, and ground contact point. Existing walk sheets remain unchanged. A left/right flip does not count as separately authored art. Renderer support is independently testable; it does not certify that the delivered art depicts genuine directions or action phases.

## Runtime manifest

Load the manifest first, then `directional-actions-v410.js`, before `hero-saga.js` and `enemy-animations.js`. The existing `v2-expansion.js` remains loaded. The manifest assigns a direct actor map to `globalThis.TD2DirectionalAssets`:

```js
globalThis.TD2DirectionalAssets = {
  marcel: {
    file: 'assets/directional-v410/marcel.webp?v=v410a1',
    cell: 192, frames: 4, anchor: [96, 178], height: 160,
    rows: {
      down:  {attack: 0, hit: 1, death: 2},
      left:  {attack: 3, hit: 4, death: 5},
      right: {attack: 6, hit: 7, death: 8},
      up:    {attack: 9, hit: 10, death: 11}
    }
  }
};
```

Actor names are `marcel`, `kim`, and `enemy-00` through `enemy-20`, using the existing `DenkmalEnemyAnimations.select(enemy, level)` identity map. Each file contains one actor, four columns and twelve rows, exactly 48 authored cells. Hero runtime cells are 192×192 (768×2304 sheet); enemy cells are 128×128 (512×1536 sheet). `anchor` is the common ground pivot in cell pixels; `height` is the reference painted body height in pixels, used to preserve existing runtime sizes. Production may choose a different anchor/painted height based on measured art, but every cell of that actor must share it.

| Direction | Attack row | Hit row | Death row |
| --- | ---: | ---: | ---: |
| Down | 0 | 1 | 2 |
| Left | 3 | 4 | 5 |
| Right | 6 | 7 | 8 |
| Up | 9 | 10 | 11 |

Source crop is `[frame × cell, row × cell, cell, cell]`. Destination uses the manifest pivot without a horizontal flip. Missing actor/action/direction, invalid dimensions, cold downloads, failed downloads and failed Canvas draws return `false` so earlier action/walk/procedural renderers remain available. Existing fallback art may mirror; it is not credited as new directional art. Omit unapproved directions from the manifest rather than registering a mirrored or unsuitable row.

## Phase and time mapping

| Action | Four columns | Hero duration | Enemy duration |
| --- | --- | ---: | ---: |
| Attack | Wind-up, strike, follow-through, recover | 0.24 s | 0.22 s |
| Hit | Impact, recoil, settle, recover | 0.16 s | 0.10 s |
| Death | Stagger, buckle, collapse, final resting pose | 0.65 s | Caller death lifetime (0.65 s currently) |

Action priority is death, hit, attack. Frame is `min(3, floor(clamp(progress, 0, 1) × 4))`. Reduced motion/low mode selects attack/hit column 2 and death column 3. Enemy death progress comes from the existing simulation death lifetime. Hero death uses the passed simulation clock (`animationTime`), including the legacy V2 fallback; repeated paused rendering does not advance death. Reaching the last pose clamps rather than loops. A stopped game-over simulation holds its death pose; the renderer does not secretly advance wall-clock time.

Hero movement/hit direction uses `hero.direction`. `HeroSaga.onAttack(target)` captures the actual target-to-hero vector as `hero.attackDirection` for the whole attack; movement updates cannot replace that aim. Legacy no-argument attacks safely capture the existing facing. Hero death captures its initial facing. Enemy attacks prefer `options.target`, then saved `targetX`/`targetY`, before velocity: a retreating archer still aims at its target. Other enemy action facing uses actual `velX`/`velY` before the target fallback. Death prefers the captured `deathDirection` and saved facing, so it does not turn toward a subsequently moving target. The dominant vector axis chooses direction, ties use the vertical axis. Without a known vector/direction the new renderer returns false. The game integration must supply the actual combat target and preserve the final heading when creating death effects.

## Loading and ownership

Only `DenkmalAssets` creates/decodes images. Directional art uses shared retained groups, starts at most two retain requests simultaneously, keeps at most 24 actor atlas states, and releases enemy groups on level change (`setLevel`, also called by V2 environment rendering). Groups use unique generation IDs so an obsolete pending load cannot release a newer owner. No `Image` allocation occurs in the renderer. Failed requests retry after a backoff; previous sprites remain active while loading. Hero groups can survive level changes.

## Author scale calibration

Separately generated direction strips can contain a smaller drawing of the same actor. `art-a.json` and `art-b.json` record visually estimated `viewScale` values (whole12-pose source direction bands) and `frameScale` for the six replaced enemy12poses. Values compare head, torso and legs rather than weapon bounding boxes. The exporter applies these author corrections around each measured contact point before choosing one common actor scale and runtime anchor. No source PNG is altered, no direction is flipped and no weapon is clipped to fit. These are documented art corrections, not automatically measured physical dimensions. The export manifest records the factor on every frame.

The source extractor separates complete isolated bodies before assigning all visible source pixels to their nearest body. It accommodates irregular row spacing, rejects merged bodies and verifies that source pixels are neither lost nor duplicated. Runtime alpha can peak at254 after resampling; the technical gate requires a fully transparent background and near-opaque painted pixels, not an artificially forced255value.

## Art and release QA

For all 23 identities, inspect all 48 cells at native and actual runtime scale: correct actor/reference, 4 genuine views, action continuity, fixed baseline, safe weapon/wing margins, true transparent RGBA, no opaque matte, no neighboring-cell leaks, no anatomy or scale drift. Check down/left/right/up in an actual browser during attack, hit, and death. Confirm identity and asymmetry against the approved walk sheets. File dimensions and transparent pixel counts alone do not prove appropriate art or real directional changes.

`node tests/directional-actions-v410.test.cjs` verifies 48 exact source crops, heading priority, missing/cold/failed art fallback, reduced poses, pause/death clock behavior, draw exception restoration, revival reset and cache release. Existing V2 and enemy animation suites cover the retained fallback path. Final directional art review, full-set completeness and visible browser acceptance remain separate release gates.

# V4.1.0 – deterministischer Karten-Feinschliff

## Umfang und Referenz

Canvas-native, transparente Boden-Overlays für alle sechs aktiven Karten. Die vorhandenen Renderer und `dist/levels.js` sind die verbindliche Geometriequelle. Es werden keine Routen, Slots, Kollisionen, Monumentanker, Kirchenmaße oder Terrassenkoordinaten verändert. Die Reihenfolge ist Einleitung, Labyrinth, Kirchende, Ender Dorfkirche, Hohensyburg, Goethestraße.

| Eigenschaft | Einordnung | Umsetzung |
| --- | --- | --- |
| Vorhandene Wege, Slots und Anker | Belegt als aktuelle Spielgeometrie | Unveränderte Referenzen aus `levels.js` |
| 0.82-Projektion / aufrechte Objekte | Belegt durch `style2-phase6.js` | Keine eigene Transformation, `upright()` bleibt erhalten |
| Getrennte Kirche / südgerichteter Löwe | Vorgabe der freigegebenen Komposition | Kirchenfläche wird ausgespart, Löwenzeichnung und Richtung bleiben vollständig beim bestehenden Renderer |
| Hohensyburg-Terrassen | Angenäherte Spielgeometrie | Raised/forecourt/stairs bleiben vegetationsfrei |
| Neue Vegetation und Materialabnutzung | Künstlerische Annäherung | Keine historische Genauigkeit behauptet |
| Exakte historische Vegetation / Vermessung | Unbekannt | Keine neue Ableitung oder Verschiebung |

Die Historical-Environments- und Style-2-Art-Director-Skills wurden gelesen. Die dort relativ referenzierten Dateien `art-bible-v1.md` und `review-contract.md` waren über den Skill-Provider nicht lesbar; die geladenen Skills und der bestehende Canvas-Stil begrenzen diesen Pass. Es wurden keine zusätzlichen Bildassets erzeugt.

## Schichten und sichtbare Änderungen

1. Bestehendes Gelände, Straße und Terrassen bleiben die Basis.
2. Unterbrochene Erdtöne und helle Stein-/Kiesakzente folgen den vorhandenen Wegsegmenten, nur außerhalb der begehbaren Straßenmitte. Keine zusätzliche Verbindung wird gezeichnet.
3. Kleine transparente Kontaktflecken verbinden Monumentfuß, südliche Kirchenfundamentkante und vorhandene Terrassenkanten mit dem Boden. Wegbereiche, Slots und Treppen bleiben an den Gebäudekanten ausgespart.
4. Flache Blatt-, Moos-, Gras- und Steincluster stehen außerhalb der Wege, Bauplätze und Monumentzone. Kirchenfläche, beide Terrassen und Treppen werden einschließlich Sicherheitsrand freigehalten. Diese Elemente sind Bodendetails, keine hohen Objekte oder neuen Kollisionswände.

Die Karten verwenden verwandte, individuell gedämpfte Erd-/Stein-/Moos-Paletten. Keine neue Architektur, keine neue Beleuchtungsanimation, keine Rotation des Löwen, keine Versetzung von Objekten.

## Integration

`dist/map-polish-v410.js` vor `game.js` laden. Das Modul exportiert `globalThis.DenkmalMapPolish`:

```js
// layout: existing level data plus center. camera/view sizes are in world units.
DenkmalMapPolish.drawGround(ctx, level, layout, camera, width, height, options);
DenkmalMapPolish.drawDetails(ctx, level, layout, camera, width, height, options);
// options: {low: lowFX(), reduced: reducedMotion}; reduced is static by design.
```

Beide Methoden liefern `false`, wenn keine gültige Karte bzw. kein Canvas verfügbar ist. Sie sind additive transparente Overlays und ersetzen niemals die bestehenden Basis-Renderer.

Verbindliche Reihenfolge im Haupt-Renderer:

```js
drawGround(); // existing base, unchanged
const polished = DenkmalMapPolish?.drawGround(ctx, game.level, layout, camera,
  W / zoom, H / (zoom * viewDepth), options);
if (!polished) Style2Phase6?.draw(ctx, game.level, layout, camera,
  W / zoom, H / (zoom * viewDepth));
drawLevel(); // existing paths, church/site and markers
DenkmalMapPolish?.drawDetails(ctx, game.level, layout, camera,
  W / zoom, H / (zoom * viewDepth), options);
// existing environment and world-object drawing, retaining upright()
```

`Style2Phase6.draw()` wird bei erfolgreichem Overlay ausgelassen, um dessen ältere Bodenvegetation nicht doppelt zu zeichnen. `Style2Phase6.depth`, `project`, `unproject` und `upright` werden nicht verändert. Bei Kartenreset `DenkmalMapPolish?.reset()` ergänzen. Hauptintegration und Browserprüfung erfolgen durch den Release-Integrator.

## Grenzen und Ausfallverhalten

- Ein aktiver Plan: höchstens 240 Vegetationscluster und 900 Wegübergangsflecken. Plan und Einträge sind eingefroren.
- Zwei transparente Atlanten, je 1536² Pixel: zusammen 18 MiB reine RGBA-Pixeldaten. Im Sparmodus je 768²: zusammen 4.5 MiB. Dies ist eine rechnerische Cachegrenze, keine gemessene Browser- oder Android-RAM-Zahl.
- Neue Karten- oder Layoutreferenzen ersetzen den bisherigen Plan/Atlas. Flache Layout-Wrapper pro Frame lösen keinen Neubau aus. Änderungen an Geometrie innerhalb derselben Referenz benötigen `reset()`; der aktuelle Spielcode verwendet unveränderliche Geometrie.
- Nach dem Warm-up nur zwei zugeschnittene `drawImage`-Aufrufe; keine neuen Canvas-, Plan-, Gradienten- oder Bilddownload-Allokationen pro Frame. Sparmodus reduziert Rasterauflösung und Vegetationsdichte; reduzierte Bewegung benötigt keine eigene Animation oder Rastervariante.
- Fehlender Canvas-Kontext wird bis Reset/Kartenwechsel/Qualitätswechsel erinnert. Kein wiederholtes Allokieren im Fehlerfall. Keine vollflächige Füllung, keine schwarzen Ersatzrechtecke, keine `Image`-Abhängigkeit.

## Prüfung

TDD: `tests/map-polish-v410.test.cjs` schlug zunächst wegen des fehlenden Moduls fehl und bestand nach Implementierung.

```sh
node tests/map-polish-v410.test.cjs
node --check dist/map-polish-v410.js
```

Die Tests prüfen alle sechs Karten, vollständige Vegetationsradien gegen Wege/Slots/Monument/Kirche/Terrassen, unveränderte Leveldaten, reproduzierbare Seeds, eingefrorene Pläne, Cachegrenzen, flache Wrapper, Sparmodus, unsichtbare Ausschnitte und kalten/fehlgeschlagenen Canvas-Zugriff. Browser-Sichtprüfung auf lesbare Routen, Kontakt und Darstellung unter tatsächlicher Kamera ist ein zusätzlicher Integrationsschritt. Keine Android-FPS-/RAM-Messung oder neue historische Verifikation behauptet.
